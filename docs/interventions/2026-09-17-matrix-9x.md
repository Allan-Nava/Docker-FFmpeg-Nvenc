# Matrix rebuilt around FFmpeg 9.0: 9.0.1 / 7.1.5 / 6.1.6 / 5.1.10 — 2026-09-17

Second change of the day to the variant matrix. The [patch bump](2026-09-17-ffmpeg-patch-bump.md) moved
each variant to the latest release of *its* branch; this one changes **which branches** are shipped.
Closes the backlog item `ffmpeg-8-and-9-variants`.

```
   before (after the patch bump)          after
   ─────────────────────────────          ─────
   7.1.5   sdk/12.1   >= 530  default      9.0.1   sdk/12.1   >= 530  default   ← new
   6.0.1   sdk/12.0   >= 530              7.1.5   sdk/12.1   >= 530
   5.1.10  sdk/11.0   >= 470              6.1.6   sdk/12.1   >= 530             ← replaces 6.0.1
                                          5.1.10  sdk/11.0   >= 470
                                              │
                                              └─ one sdk/12.1 now covers three of the four rows
```

## The measurement this rests on

The `ffnvcodec` floor of every maintained FFmpeg branch, read from each release's `configure`:

| branch | latest | `ffnvcodec >=` | lowest branch that works |
|---|---|---|---|
| 5.1 | 5.1.10 | 9.1.23.1 | `sdk/11.0` |
| 6.0 | 6.0.1 | 12.0.16.0 | `sdk/12.0` |
| 6.1 | 6.1.6 | 12.1.14.0 | `sdk/12.1` |
| 7.0 | 7.0.3 | 12.1.14.0 | `sdk/12.1` |
| 7.1 | 7.1.5 | 12.1.14.0 | `sdk/12.1` |
| 8.0 | 8.0.3 | 12.1.14.0 | `sdk/12.1` |
| 8.1 | 8.1.2 | 12.1.14.0 | `sdk/12.1` |
| 9.0 | 9.0.1 | 12.1.14.0 | `sdk/12.1` |

**From 6.1 onwards the requirement never moves.** That is the whole reason this change is cheap: adding
9.0.1 as the default asks **nothing more of the host's driver** than 7.1.5 did (≥ 530 either way), and
swapping 6.0.1 for 6.1.6 moves that variant onto a maintained branch at the same floor.

Why these four and not more:

- **9.0.1 default** — the current release. Anything newer than 6.1 is free in driver terms, so there is no
  argument for keeping an older default.
- **7.1.5 kept** — the conservative choice for anyone who does not want a major bump; it is also the branch
  most downstream tooling currently expects.
- **6.1.6 instead of 6.0.1** — 6.0 is superseded by 6.1 *inside the same major*: staying on 6.0 meant
  shipping a branch nobody maintains. This is the one row where the `sdk/*` branch changes (12.0 → 12.1),
  with no change to the driver floor.
- **5.1.10 kept** — the only row with a lower floor (≥ 470). It exists for hosts that cannot move drivers,
  which is exactly the situation where an old FFmpeg is acceptable.
- **8.0 and 8.1 skipped** — they sit between two rows that are already shipped and cost the same driver as
  both. Every matrix row is a ~90-minute build on every tag; four is already 6 hours of CI per release.

`sdk/12.2` and `sdk/13.0` exist upstream (plus `n13.1.15.0` tags) and stay unused on purpose: no variant's
`configure` asks for them, and a higher branch only raises the host requirement. If a future NVENC feature
needs one, its driver floor has to be checked against NVIDIA's matrix first and written into the README table.

## Verification

Run with the new helper script, which reads the matrix from the publish workflow so it cannot test a
different set from the one CI publishes:

```shell
LOG_DIR=logs/2026-09-17-matrix-9x ./tests/build-matrix.sh
```

Native `linux/arm64` builds (the workstation is Apple Silicon; published images are `linux/amd64` and CI
builds those). Raw logs in [`logs/2026-09-17-matrix-9x/`](../../logs/2026-09-17-matrix-9x/).

| 7.1.5 | `sdk/12.1` | OK | **17 ok, 0 fail** | 203 MB | `ffmpeg version 7.1.5` |
| 6.1.6 | `sdk/12.1` | OK | **17 ok, 0 fail** | 202 MB | `ffmpeg version 6.1.6` |

Worth stating explicitly, because it was the risk of this change: **FFmpeg 9.0 needed no changes to the
`./configure` line** — every `--enable-*` in the Dockerfile is still valid, the bookworm build dependencies
still cover it, and the NVENC gates inside the Dockerfile (both stages) passed. The image grew 2 MB.

⚠️ **Not verified here**: real NVENC encoding (`tests/gpu.sh`, needs an NVIDIA host) and the `linux/amd64`
build, which is what CI does. Both remain gates before promoting a tag (`gpu-gate-before-tag`).
